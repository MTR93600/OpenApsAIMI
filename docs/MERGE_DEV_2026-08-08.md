### `invalidInputs` divergence — resolved (follow-up to 2026-08-03)

The 2026-08-03 log left the `OpenAPSSMBPlugin` ↔ `OpenAPSAIMIPlugin` `invalidInputs` gap open, and
concluded that "only the `TDD` check and the abort observability are actually missing". Re-read
against the post-merge code, **that conclusion was wrong in an important way**: the risk is not a
zero or missing TDD, it is a **NaN** one.

- `TDD <= 0.0` **cannot happen in AIMI**. Unlike SMB, AIMI always has a TDD: it falls back to the
  `OApsAIMITDD7` preference (declared `40.0, min 1.0, max 150.0`). Adding that half of the check
  would be dead code, and gating it on the raw `dynIsfMode` (no `tddPartsCalculated()` equivalent
  exists in AIMI) would have been the wrong fix for a problem that does not exist.
- `insulinDivisor <= 0` is equally dead: AIMI's divisor is a `when` on the peak returning 45/55/65.
- **The real hole is NaN.** The four floors that build AIMI's TDD all test `== 0.0` / `< tdd7P`, and
  every comparison with NaN is false, so a NaN passes all four untouched:
  `OpenAPSAIMIPlugin` lines ~1008 (`tdd2Days`), ~1018 (`tddDaily`), ~1026 (`tdd24Hrs`) and
  `DetermineBasalAIMI2` ~1677 (`tdd7Days`). Downstream, the `tdd7Days.toFloat() != 0.0f` guards in
  `DetermineBasalAIMI2` are **true** for NaN, so it would enter those branches and make
  `basalaimi` (`tdd7Days / weight`) and `ci` (`450 / tdd7Days`) NaN for the whole tick.
- `variable_sens` is clamped by `coerceIn(5.0, 300.0)` just before use, so the `<= 0.0` half of its
  guard is dead — but `NaN.coerceIn(...)` returns NaN, so the `!isFinite()` half stays live and useful.

**Applied (this branch, uncommitted at the time of writing):**

| Fix | Where | Note |
|-----|-------|------|
| `!x.isFinite() ||` prepended to the four TDD floors | `OpenAPSAIMIPlugin` ×3, `DetermineBasalAIMI2` ×1 | Root fix. **No behaviour change for any finite value** — the existing `== 0.0` / `< tdd7P` conditions are untouched. |
| `!oapsProfile.TDD.isFinite()` added to `invalidInputs` | `OpenAPSAIMIPlugin` | Backstop only. **Not** gated on `dynIsfMode`, and **without** `TDD <= 0.0`, for the reasons above. |
| `fabricPrivacy.logException()` + `EventOpenAPSUpdateGui()` on abort | `OpenAPSAIMIPlugin` | Parity with SMB. `FabricPrivacy` added to the constructor (Dagger only — no manual construction or subclass of the plugin exists). Without these the abort never reached Crashlytics and the APS card kept showing the previous run. |
