## Key findings and corrections
- OApsAIMIcombinedDelta and OApsAIMIAutodriveAcceleration are weights, not thresholds: combinedDelta = (delta + wS*shortAvg + wL*longAvg)/(1 + wS + wL). The UI titles and summaries are misleading.
- OApsAIMIMLtraining is not training-only. It gates ML refine of the SMB and the hyper boosts x1.7 (BG>170, delta>4) and x1.5 (BG>150, delta>3) while IOB < ApsSmbMaxIob.
- SMB tail damping value is a multiplicative floor: lower = stronger damping (0.70 = up to -30%, 1.0 = off). Values <= 0.55 are read as 0.85 (legacy).
- Mode Factor default 50 means the SMB is multiplied by 0.5 in meal modes. In ticks without a mode only the learner factor applies.
- ApsMaxSmbFrequency is not the SMB interval. It sets the periodic fallback loop period with autodrive. The SMB interval comes from the mode interval keys and calculateSMBInterval.
- ApsMaxMinutesOfBasalToLimitSmb and ApsUamMaxMinutesOfBasalToLimitSmb are only passed to the profile; the AIMI engine does not apply them (AAPS-side cap not verified: uncertain).
- Manual advice to change KickerStep, ZeroResumeMin and NightGrowthBasalMultiplier is outdated: those keys are dead. NGR live keys: Enabled, AgeYears, Start, End, MaxIobExtra. Other NGR values come from NightGrowthResistanceLearner.
- ContextLLM* provider and key settings are dead: ContextLLMClient reads the AimiAdvisor* keys.
- OApsAIMIBasalChannelSafetyGuards: key default is true; the KDoc saying false is stale.
- TPO may overwrite 15 keys transiently (LOOP writer): MaxSMB, HighBGMaxSMB, PriorityMaxIobFactor, PriorityMaxIobExtraU, PkpdPragmaticReliefMinFactor, RedCarpetRestoreThreshold, SmbTailDamping, SmbExerciseDamping, SmbLateFatDamping, LunchFactor, DinnerFactor, AimiTubeAggressiveness, AimiTubeHypoFloorMgdl, PkpdPragmaticReliefEnabled, StraightLineTubeAdvisorEnabled. The AIMI Assistant can write HighBGinterval, PriorityMaxIobExtraU, HighBGMaxSMB, MaxSMB, RedCarpetRestoreThreshold. A value you set may be changed for a while; check the value after a loop run.
- Dead keys (no readers): forcelimits, EnableBasal, PlateauBandAbs, R2Confident, AutodriveV3EnhancedGater, AutodriveDeviation, AutodriveBG, FCLFactor, NightGrowth MinRiseSlope/SmbMultiplier/BasalMultiplier/MaxSmbClamp, ContextLLM Provider and four API keys, plus the manifest DEAD_KEYS set.

## Relationships
Order of application, per tick. Approximate where marked. Key names are shortened (drop OApsAIMI).

### 1. SMB size
1. ML refine and hyper boost (only if MLtraining on; hyper boost only while IOB < ApsSmbMaxIob).
2. Mode factor: base x (mode Factor %/100 x learner factor). Default 50 = x0.5. Honeymoon (Child mode) x0.8 if BG<170.
3. PI term and MPC dose search, bounded by maxSmb; blend by SmbMpcPiBlend.
4. Safety hook, then SmbDamping: late fat x tail x exercise (SmbLateFatDamping, SmbTailDamping/Threshold, SmbExerciseDamping).
5. HighBG PKPD x1.2 boost (not in T3C brittle mode), HighBgOverride, quantize to pump step.
6. PKPD absorption guard (floor = PkpdPragmaticReliefMinFactor in priority context), endometriosis dampen (endoSmbMult), Red Carpet restore (RedCarpetRestoreThreshold, min 0.60), cap = min(candidate, max(maxSMB, maxSMBHB), IOB headroom, 30).
7. Activity cap 0.5 x maxSMB, meal high-IOB damping, interval gate (see 4).
8. Final: applySafetyPrecautions (below target /2; falling-decelerating x0.5 near target; honeymoon /2), IOB surveillance, RiseCeilingGuard, HTR floor, Tube scale, context ceiling, Auditor modulation. Order of these late gates is approximate (uncertain).

### 2. maxSMB / maxSMBHB
- maxSMB = MaxSMB; maxSMBHB = HighBGMaxSMB (forced >= MaxSMB).
- MaxSmbLadder: BG>=250 and combinedDelta>-5 -> HB; confirmed rise at BG>=140 (slope>=1.0 or shortAvgDelta>=8, combinedDelta>0.5) -> HB; BG 120-140 with slope>=1 -> max(maxSMB, 0.85 HB); BG 200-250 flat -> 0.75 HB; BG>180 falling -> 0.6 HB; else maxSMB. BG<120 forces <= MaxSMB.
- Executor and PKPD-stage cap use HB if one-shot, or (BG>120, not honeymoon, slope>=1), or (meal mode and BG>100); else the ladder result.
- Then Tube advisor scales both (scale <= 1, keys AimiTube*), TPO may overwrite both, Assistant may overwrite both.

### 3. IOB limit
ApsSmbMaxIob -> maxIob (static) -> AAPS constraint min(pref, hard limit) -> context safetyMarginExpand -> NGR night headroom (MaxIobExtra x slot cap, absolute cap pref + slot budget) -> priority context (needs PkpdPragmaticReliefEnabled and meal mode / one-shot / confirmed rise): min(maxIob x PriorityMaxIobFactor, maxIob + PriorityMaxIobExtraU), cap 25 -> meal debridage target 6-12 U (up to 25). IOB above limit blocks SMB unless meal high-IOB relax applies. Effective-IOB release changes the compared IOB, not the limit.

### 4. SMB interval
delta>15 -> 1 min (skips the rest). Else mode interval key (Snack/Meal/BF/Lunch/Dinner/Sleep/HC), else HighBGinterval if BG>120 (honeymoon >180), else 3. Then sport safety or low-carb >=10; strong activity >=15; BG<target x2 (cap 20); honeymoon BG<170 and delta<5 x2; night 23h x0.8 (delta<10, IOB<maxSMB). Clamp 1..10 (so any value 11-20 acts as 10); BG<120 -> min 5. PKPD throttle add (BG>=120) capped at 10. ApsMaxSmbFrequency is not part of this.

### 5. Basal rate
Base cap: meal_modes_MaxBasal (manual meal mode) / autodriveMaxBasal (early autodrive) / ApsMaxBasal; raised to max daily basal if lower. Special modes return before ApsMaxCurrentBasalMultiplier and ApsMaxDailyMultiplier caps. Upstream order: adaptive basal (H channel 0.70..MaxMultiplier; N channel limited by AdaptiveBasalMaxScaling and governance HOLD floors) -> T3C aggressiveness cap -> W-cycle / endometriosis / pregnancy / honeymoon / NGR multipliers -> ActivityBasalCapFactor (exercise lockout) -> slew limit (up only) -> terminal invariants and stack caps -> T3C hyper floor. meal_modes_MaxBasal also sets the forced 30 min TBR in meal modes.

### 6. TPO whitelist
TPO (LOOP writer) overrides the 15 keys listed above for a limited time; user value is restored after. Set the underlying key only when TPO is off, or expect a mismatch.

### 7. Mode factor resolver
resolved = manual% / 100 x learner (learner = 1.0 if UnifiedReactivity off). The 0.60-1.60 clamp is applied to `factors` (activity target, safeCapped branch), not to the dose multiplier.

## Symptom map
Direction: up = increase value, down = decrease value (or switch off). Always change one setting at a time.

### Overshoot after meals (high peak)
1. Mode Factor (Reactivity) of that meal: up. Default 50 halves the SMB.
2. Mode Prebolus 1/2 and 2/2: up. Gives insulin before the rise.
3. Mode SMB interval: down. More frequent SMB (min 1).
4. HighBGMaxSMB: up. Bigger SMB when BG is high and rising.
5. RedCarpetRestoreThreshold: up. Restores more of the damped SMB.
6. PriorityMaxIobFactor / PriorityMaxIobExtraU: up, and PkpdPragmaticReliefEnabled on. More IOB room in meals.
7. PkpdPragmaticReliefMinFactor: up. Absorption guard cuts less.
8. SmbTailDamping: up toward 1.0 (weaker damping), or SmbTailThreshold: down. Less cut late in the insulin tail.
9. ApsSmbMaxIob: up if IOB limit is the blocker (check log).
10. Enable HTR, aggressive floor, MealConfirmedEarlyRelease, TreeMealRiseFrontLoad (uncertain names; see table).

### Late reaction (slow start)
Same list as overshoot, plus: combinedDelta and AutodriveAcceleration weights (they are weights; lower weights make combined delta follow the current delta faster); check blockers IobSurveillanceGuard, RiseCeilingGuard (off or relax); HighBGinterval: down; MLtraining: on (enables hyper boosts).

### Lows after meals or after SMB
1. MaxSMB and HighBGMaxSMB: down.
2. Mode Factor: down.
3. Mode interval: up.
4. SmbTailDamping: down toward 0.70 (stronger); SmbLateFatDamping and SmbExerciseDamping: stronger.
5. IobSurveillanceGuard and EffortActivityProtection: on.
6. Target: up.
7. ApsSmbMaxIob: down; PriorityMaxIob*: down.
8. RedCarpetRestoreThreshold: down (restores less).
9. MaxMultiplier, AdaptiveBasalMaxScaling, T3cAggressiveness: down; GovernanceHypoRateEnter: down (enter hold sooner; uncertain direction semantics, check title).
10. MLtraining: off removes the x1.5/x1.7 hyper boosts.

### Night lows
Sleep Factor: down. Sleep interval: up. Check Child mode (Honeymoon). NGR: MaxIobExtra down or NGR off. Do not use NightGrowth Basal/Smb multipliers: dead.

### Plateau highs (stays 180-250)
HighBGinterval: down. HighBGMaxSMB: up. HyperDroppingExemptEnabled: on. PriorityMaxIob*: up. MaxBasal / ApsMaxBasal: up if basal is capped.

### High variability (up and down swings)
Lower HighBGMaxSMB, raise mode intervals, keep Factor near default, use SmbTailDamping stronger, turn TPO and Tube advisor off to test one change at a time.

### Pump does nothing though BG is high
Check in order: IOB above ApsSmbMaxIob; interval gate; MaxSMB ladder result (BG<120 forces MaxSMB); mode Factor too low; IobSurveillanceGuard or RiseCeilingGuard blocking; exercise lockout (ActivityBasalCapFactor); TPO overwrote a key.
