## 3. R-CB, autres échecs, tests, `TrainingResult`

### 3.1 Effet dose de R-CB

`refine()` retourne `predictedSmb` inchangé quand le disjoncteur est ouvert (study L173, tip L355). La correction ML reste bornée à `min(0.05f, predictedSmb * 0.25f)` (study L349, tip L704) **seulement si** le disjoncteur est fermé et qu’un modèle est en mémoire. Les poids ne sont pas effacés par `recordFailure()`.

Le tip (`AimiSmbTrainer.kt` L544–556) n’appelle `recordFailure()` dans le `else` de `net == null` que si `modelRef.get() == null`. Le study fait le même test :

- argument : `modelRef.get() != null` (L309) ;
- prédicat : `!modelInService` (schedule L156) ;
- donc `recordFailure()` ssi `modelRef.get() == null`.

Un modèle déjà chargé n’est pas coupé par une candidate rejetée. Sans modèle en mémoire, le rejet compte, et le troisième ouvre le disjoncteur. C’est le cas que le tip décrit L548–550 : rien n’est encore en service.

Le commit source remplace, dans ce même `else`, un `recordFailure()` inconditionnel par le `if (modelRef.get() == null)`. `59aeb50833` remet ce garde. Le head `d47f71d517` ne l’avait pas.

Le garde lit `modelRef`, pas le fichier de poids. Un fichier sur disque avec `modelRef` encore null compte comme un échec, des deux côtés.

### 3.2 Autres chemins d’échec

Le diff `59aeb50833` ne change que le `else` de `net == null`. Les autres appels de `recordFailure()` sont ceux du tip :
