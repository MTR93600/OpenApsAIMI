## 3. Fidélité clinique vs tip

### 3.1 Helper — decide-at-revert, pas de sticky

Relu côte à côte `a546722609:plugins/aps/src/main/.../tpo/TpoRevertPolicy.kt` (blob `5c56e5ab`, = `acdc2b118e`) vs `8d3d01bb5e:plugins/aps/src/commonMain/.../tpo/TpoRevertPolicy.kt` (blob `8a677b46`).

Diff réel : `object` → `internal object`. **Zéro** changement de formule. `diff` après substitution de visibilité : **vide**.

Règles (ordre, identiques) :

1. `liveValue == null` **ou** `overlayValue == null` → `false` (clé illisible ou jamais écrite : pas de write).
2. Sinon `sameValue(live, overlay)` seulement.
3. `observedDivergence` est un paramètre **ignoré** (`UNUSED_PARAMETER`). C’est exactement la stickiness que le tip a retirée.
4. `sameValue` : deux `Number` → `abs(a.toDouble() − b.toDouble()) < 0.0001` ; deux `Boolean` → `==` ; sinon `toString()`.
5. Un `Int` relu (JSON sans décimale) et un `Double` overlay **passent** par la branche `Number` — jamais `"1.0" == "1"`.

`f3de6740` n’est **pas** le contrat `sameValue` porté : comparait encore `Double` seulement. Study = `acdc2b118e` / tip.

Le helper est **pur** (pas d’horloge, pas d’Android, pas de `Locale`/`Hilt`/`File`). Il ne calcule aucune U.

### 3.2 SessionManager — restore du baseline si live == overlay

Base study (`a5067a028b` L187) :

```
if (key in session.userOwnedKeys) return@forEach
if (restoreValue(...)) restored++
```

P3.6 = tip `f3de6740` / `acdc2b118e` / `a546722609` :

```
val liveValue = readPreferenceValue(preferences, key)
val sessionWrote = session.overlay[key]
if (!TpoRevertPolicy.shouldRestore(liveValue, sessionWrote, key in session.userOwnedKeys)) {
    skipped++
    return@forEach
}
if (restoreValue(preferences, key, oldValue)) restored++ else refused++
```

Identique tip L195–201 ≡ study L197–203. Compteurs + log `TPO revert ($reason, $restored keys, $skipped skipped, $refused refused)` = tip `acdc2b118e` L210 ≡ study L212.

`trackUserOwnedKeys` continue d’écrire `userOwnedKeys` pendant `expireIfNeeded` (diagnostic, comme le tip). Il ne gouverne plus le restore.

`revertNow` / `expireIfNeeded` / `supersedeActiveSession` passent toujours `nowMs` pour le statut ; le revert expire n’a pas de `lastRevertAtMs` sur le copy → fallback horloge. **Identique au tip** sauf l’implémentation de l’horloge (voir §4 / §6).

### 3.3 `applyChange` Number — deuxième ligne de défense

Tip `acdc2b118e` L268–269 ≡ study L270–271 :

```
newValue is Number && key is DoublePreferenceKey -> {
    preferences.put(key, newValue.toDouble())
```

Sans ça, un baseline relu comme `Int` était refusé et le restore perdait silencieusement la valeur user. `TpoPreferenceKeys` (blob `79c90cd8`, **identique** tip/study/base) n’est pas touché : whitelist MaxSMB / HighBGMaxSMB / IOB / damping / meal factors / tube.

`jsonToMap` study **n’est pas** le tip `acdc2b118e` (study peut encore produire un `Int` pour un entier JSON ; tip normalise tout `Number` en `Double`). Hors lot, annoncé. C’est précisément pourquoi `applyChange` `Number` + `sameValue` `Number` sont le contrat porté — pas une réécriture `jsonToMap`.

### 3.4 Prefs / impact dose

Le lot **ne change pas** le calcul de dose APS (pas de DetermineBasal, pas de DPA, pas de formule U).

Il **restaure** les prefs de la whitelist TPO quand l’overlay est encore live en fin de session. Si quelqu’un d’autre a bougé la clé, le session **la laisse**. Une divergence transitoire plus tôt **n’empêche plus** le restore.

Dose-adjacent **via prefs** : `DetermineBasalAIMI2` lit `DoubleKey.OApsAIMIHighBGMaxSMB` (`maxSMBHB`, hors diff #111). Remettre 2.0 à la place d’un overlay 1.25 change le plafond SMB **au tick suivant**, comme le tip. Ce n’est pas une nouvelle formule study.
