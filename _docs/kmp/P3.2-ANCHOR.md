## 3. Fidélité clinique vs `f61474bb73`

### 3.1 `StressIsfFloor` — signature et hold

Relu côte à côte `f61474bb:plugins/aps/src/main/.../ISF/StressIsfFloor.kt` vs `459b48d66f:plugins/aps/src/commonMain/.../ISF/StressIsfFloor.kt`.

Règles (ordre, identiques) :

1. `hrNowBpm <= 0` **ou** `rhrRestingBpm <= 0` → inactif, `REASON_NO_HR`. 0 = donnée manquante, pas un patient calme.
2. Signature : `excessBpm >= 20` **et** `stepsLast15m < 250`.
3. Entrée ≠ sortie : on après **10 min** ininterrompues ; off après **5 min** hors signature (grâce), plafonnée à **20 min** si l’échantillon HR n’a jamais bougé.
4. Gap `> 10 min` (ou horloge arrière) casse la continuité ; un floor actif **tombe tout de suite**, pas de grâce.
5. Rise-hold : si déjà actif, `deltaMgdl5m` fini et `>= 11`, pas de gap → le floor **reste**, `REASON_RISE_HOLD`. Un HR manquant ou un gap **droppe** quand même.

Dose : l’objet est pur. Le geste dose est le `floorMultiplier` passé à `DynamicSensitivityPolicy.floorAgainstProfile`. `maxOf` → le résultat n’est **jamais** sous la commande. Armé = 1.0× profil du moment. Désarmé = 0.5× (comportement précédent, bit-identique — test grille `isEqualTo` sans tolérance).

Chemin ISF : `OpenAPSAIMIPlugin` écrit `OapsProfileAimi.sens = commandedIsfMgdl` **après** le floor. C’est `profile.sens` (commande), pas `variableSensitivity` (chemin P3.1).

### 3.2 Pref OFF + ombre

`BooleanKey.OApsAIMIStressIsfFloor.defaultValue = false` (tip et study). Call-site :

```
stressFloorMultiplier =
    if (stressVerdict.active && stressFloorArmed) StressIsfFloor.ARMED_FLOOR_MULTIPLIER
    else DynamicSensitivityPolicy.PROFILE_RELATIVE_FLOOR
```

Désarmé : même 0.5× qu’avant P3.2. Le verdict et `stress_isf_floor_*` partent quand même. `lastStressIsfFloorIsfMgdl` n’est rempli que si la signature est active **et** que 1.0× changerait vraiment la valeur (absent ≠ zéro).

### 3.3 `HeartRateCarryForward`

Relu côte à côte. `resolve` **byte-identique** hors KDoc source.

- Fresh `hrNow > 0` → stamp `nowMs` ; moyenne = fresh ou, si 0, le point.
- Sinon, si précédent ≤ 0 ou `measuredAt <= 0` → `MISSING` (0 / 0 / 0).
- Âge `< 0` ou `> 15 min` → drop.
- Sinon on **garde** `previousMeasuredAtMs` (pas de redatage).

Call-site repo : remplace `hrNow = if (snapshot.hrNow > 0) snapshot.hrNow else lastSnapshot.hrNow` (redatage composé) par `HeartRateCarryForward.resolve`. Tip : `System.currentTimeMillis()` ; study : `aimiWallClockMs()` — **même horloge AIMI** déjà utilisée par le snapshot study.

Consumers : un HR porté au-delà de 15 min tombe à 0, que `StressIsfFloor` lit déjà comme absence (`hrNowBpm <= 0`).

### 3.4 Rise-hold lié `9d0e`

Même seuil **11.0 mg/dL / 5 min** que P3.1 `HeartRateTrendIsf.RISE_SUSPEND` et `UndeclaredCobEstimator.HR_GATE_RISE_SUSPEND` — **trois objets, trois call-sites**, pas un collage. Ici le 11.0 **empêche le HR de retirer un floor réduction-only**. Ce n’est pas le ×0.9.
