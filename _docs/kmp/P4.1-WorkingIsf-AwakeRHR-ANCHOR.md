## 3. Détail des trois gestes

### 3.1 WorkingIsf

Ordre dans `finalize`, des deux côtés :

1. `working.coerceIn(5.0, 300.0)`
2. `× physioIsfFactor` (le facteur n’est pas re-clampé dans cet objet)
3. plancher gardé seulement s’il est fini et `> 0`
4. `max` avec la valeur d’avant plancher, puis `coerceIn(5.0, 300.0)` sur la valeur plancher

`raiseToStressFloor` est le même `max`, idempotent. Un plancher nul, négatif, NaN ou infini laisse la valeur d’avant.

Call-sites study, dans l’ordre d’exécution du tick (`DetermineBasalAIMI2.kt`) :

1. L17874 `runTrajectoryContextModuleTddIsfAndDynamicPbolusPrep` → L10271 `raiseToStressFloor` (assemblage, repli AutodriveV3).
2. L18101 `runPostBasalBootstrapIobTickStepsAndHeartRate` → L6237 `HeartRateTrendIsf.multiplier` (le ×0,9 déjà ancré en P3.1).
3. L18129 `applyEndoAndActivityAdjustments`.
4. L18137 `applyIsfBoundsAndPhysioMultipliersAfterEndoActivity` → L6460 `WorkingIsf.finalize`.

Le tip a le même enchaînement (L18381, L18618, L18654). À l’intérieur de `applyIsfBounds…`, le tip appelle ensuite `applyAuditorIsfFactorToWorkingIsf` (L6660). Cette ligne n’existe pas dans le study. Elle vient de `b7e05f3037`, pas de `6a6561caab`.

`stress_floor_isf_mgdl` reste `null` tant que la clé est off ou que la signature n’est pas active (plugin L1543–1545). `finalize` est alors le chemin sans plancher.

### 3.2 AwakeRestingHeartRate

`estimate` (`AwakeRestingHeartRate.kt` L93–105) :

- échantillon rejeté si bpm non fini ou `≤ 0`, si `stepsLast15m > 50`, ou si l’heure locale n’est pas dans `[6, 23)` ;
- `null` si moins de 50 échantillons utilisables ou moins de 3 jours locaux distincts ;
- rang = `ceil(0.10 * n)`, borné à `[1, n]`, valeur = échantillon trié d’indice `rang - 1` ;
- `null` si cette valeur n’est pas finie ou est `≤ 0` ; sinon `toInt()`.

Jour local : study L114–115 `localDay(...): Long` = `date.toEpochDays()`. Tip : `toLocalDate().toEpochDay(): Long`. Même clé de jour. Le commit `e57b5d91d4` déclarait `Int` ; `f9a9cde557` l’aligne sur `Long`.

Câblage (`HealthContextRepository.kt`) : refresh `AWAKE_RESTING_REFRESH_MS = 60 * 60 * 1000L` (L62 ; tip L57), fenêtre `WINDOW_DAYS * 24 h` (L317), appariement pas si l’enregistrement n’est pas plus récent que la FC et a au plus `STEPS_MATCH_WINDOW_MS = 5 * 60 * 1000L` (L72 / L358 ; tip L67 / L365). Horloge study : `aimiWallClockMs()` = `Clock.System.now().toEpochMilliseconds()` (`AimiWallClock.kt`). Tip : `System.currentTimeMillis()`. Même unité, horloge murale.

Plugin L1488–1491 : `awakeRestingHeartRateBpm()` nul ou en échec → `rhrRestingBpm = 0`. `StressIsfFloor.evaluate` L261–274 : si FC ou repos `≤ 0`, verdict inactif, `signatureSinceMs = null`, pas de grâce, pas de rise-hold. Si la FC est `> 0` et le repos ne l’est pas, la raison commence par `no_baseline`.

### 3.3 Boost basal fenêtre repas

`BasalDecisionEngine.kt` L492–500, identique au tip L489–498 :

```
sensitivityRatio =
    si variableSensitivity > 0.1
       et preFloorCommandedSens fini et > 0
    alors preFloorCommandedSens / variableSensitivity
    sinon 1.0
boost = max(1.0, sensitivityRatio)
multiplier = delta * boost
```

Ce n’est pas `profileSens / variableSensitivity`. Le champ `profileSens` existe encore sur `Input` ; il n’est pas le numérateur de ce boost.

`OapsProfileAimi.pre_floor_isf_mgdl` (study L88, tip L93) reçoit `preFloorIsfMgdl.takeIf { it.isFinite() && it > 0.0 }` (plugin L1615 / tip L1618), avec `preFloorIsfMgdl = profile.getIsfMgdl(...) * physioMults.isfFactor` lu avant `CommandedIsf.floorAgainstProfileAndRecordShadow`. L’écriture n’est pas dans un `if (stressFloorArmed)`.

Tests : 36,6 / 21,6 avec commande plancher 60 → taux 5,08 (tolérance 0,05), et le taux ne change pas quand la commande passe de 36,6 à 60. `preFloor` `null` ou `NaN` → taux 3,0 (delta × 1). Study : `MealWindowBasalBoostTest.kt` L70–95. Tip : `BasalDecisionEngineTest.kt` L226–251. Le fichier de test tip entier (mockk) n’est pas recopié ; les quatre verrous du numérateur le sont.
