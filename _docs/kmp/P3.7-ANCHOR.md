## 3. Fidélité clinique vs tip

### 3.1 Constante 4h

Relu côte à côte `a546722609:plugins/aps/src/main/.../learning/BasalMlTrainingCoordinator.kt` (blob `141cdb173d`, = `b4f5704564`) vs `9c981d0764:plugins/aps/src/androidMain/.../learning/BasalMlTrainingCoordinator.kt` (blob `809f9f345b`).

Tip L111–120 ≡ study L120–128 (KDoc + constante) :

```
private const val STALE_TRAINING_MS = 4L * 60 * 60 * 1000 // 4h
```

`4 × 3_600_000 = 14_400_000`. 4× `TRAIN_INTERVAL_MS` (1h). Commentaire « never fires during normal hourly operation » / « never silently stale for more than about half a day » = tip. **Zéro** changement de seuil.

### 3.2 Gate force-training

Tip L197–209 ≡ study L203–218 (commentaire bootstrap déjà sur le tip **avant** `b4f570` ; paragraphe stale ajouté par `b4f570` ; condition) :

```
val trainingIsStale = now - lastTrainMs.get() > STALE_TRAINING_MS
if (!bootstrapNeeded && !trainingIsStale && newRows < MIN_NEW_ROWS) {
    log.debug(..., "$TAG: only $newRows new rows (need $MIN_NEW_ROWS) — skip")
    return TrainingOutcome.SKIPPED
}
```

Ordre des gates **inchangé** vs tip (et vs base study pour le préfixe) :

1. circuit breaker
2. rate-limit 1h **sauf** bootstrap
3. CSV missing / parse fail
4. log `label set` (preuve « on a passé le parse »)
5. **MIN_NEW_ROWS** — skip seulement si modèle déjà là **et** pas stale **et** `< 80` nouvelles lignes
6. ensuite `BASAL_MIN_ROWS` / `T3C_MIN_ROWS` (planchers de corpus, **hors** hunk P3.7)

Le bypass stale **ne peut pas** entraîner sur un corpus trop petit : les planchers plus bas restent. Il force seulement un **essai** quand les lignes s’accumulent plus lentement que 80 / 1h.

Base study (`dde9b5e27a` L193) : `if (newRows < MIN_NEW_ROWS)` — skip même en bootstrap, pas de stale. Le port aligne la **condition entière** sur le tip (bypass bootstrap **déjà** présent côté tip avant `b4f570`, plus `!trainingIsStale`).

Commentaire `6h window` → `1h window` : identique `b4f570` (commentaire seulement ; le rate-limit était déjà 1h).
