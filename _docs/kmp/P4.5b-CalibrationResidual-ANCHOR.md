## Horloge et notifications

La détection pure prend `now` en argument. Le plugin le fournit avec `dateUtil.now()`, comme le reste de `calibrate`. Aucun `System.currentTimeMillis()` ni `Clock.System` ajouté. `aimiWallClockMs` vit dans `:plugins:aps` et n’est pas une dépendance de `:plugins:calibration` (même raison que l’ancre P4.5 pour ONE+).

L’action « ignorer » passe par `NotificationAction` + `NotificationManager.post`, l’abstraction déjà utilisée par « Mark sensor change ». Le libellé est `CalibrationStrings.sensor_change_detected_ignore` (« Not a new sensor », texte ref `strings.xml`). La feuille in-app (`NotificationBottomSheet`) appelle `action.action()` pour chaque bouton.

Ce qui n’est pas nouveau, et qui n’est pas inventé ici : le tiroir Android ne montre une notification système que si `actions` est vide (`AndroidSystemNotificationPlatform`), et la catégorie iOS enregistre `actions = emptyList()` (`IosSystemNotificationPlatform`). Les deux boutons se répondent dans la feuille in-app, pas depuis le tiroir système. Aucun `android.*` n’entre dans commonMain.
