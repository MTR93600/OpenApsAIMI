## 3. Fidélité clinique vs `f61474bb`

### 3.1 Ce que le tip fait (relu, pas inventé)

Jusqu’à `9d0e9bdb9f` le geste HR était inline, **sans** rise-suspend ni baseline réelle :

```
heartRateTrend = avg10/avg60
if (steps10 < 100 && trend > 1.1 && bg > 110) variableSensitivity *= 0.9f
```

C’est encore l’état de la study base `90a95b7b` (log `ISF réduit de 10% (tendance FC anormale).`).

Sur `f61474bb` / `9d0e9bdb9f` :

1. **HeartRateTrendIsf** — seul chemin HR qui **renforce** une dose (ISF ↓ → dose ↑). Fires ssi **toutes** les conditions : baseline mesurée, nombres finis, `hr10>0` et `hr60>0`, steps10 < 100, bg > 110, **Δ5m < 11**, `hr10/hr60 > 1.1`. Sinon `1.0`. Pas de `BooleanKey`. Always-on au sens pref.
2. **Rise-suspend = 11.0 mg/dL / 5 min** — même valeur / raisonnement (cortisol empirique max 9.1) que `StressIsfFloor.RISE_HOLD` (P3.2, hors lot) et que le gate COB.
3. **Gate COB HR** (`5220fc5e2f`) — `hrInflammationElevated` ne mute plus si `deltaMgdl5m >= 11` (NaN → le gate HR **reste**). Les autres gates (false-meal, post-hypo, hypo, CFRD, exercice) tiennent pendant une montée rapide.

### 3.3 Chemin dose-facing (ordre clinique, relu)

1. Fusion ISF → local `sens` (`sensInit` / `runTrajectoryContextModuleTddIsfAndDynamicPbolusPrep`). `variableSensitivity` part de cette fusion.
2. `runPostBasalBootstrapIobTickStepsAndHeartRate` peut faire `variableSensitivity *= 0.9` et loguer `HR_TREND_ISF`. **Ne touche pas** `sens`.
3. Immédiatement après : `runBasalAimiTddCarbLimitsTirEarlyBasalAndPaiIsf(..., paiBaseSensitivity = sens)` → `newVariableSensitivity = paiBaseSensitivity` → PAI éventuellement ×0.60/×0.90/×0.95 → **`this.variableSensitivity = newVariableSensitivity`**. Le ×0.9 HR est **écrasé**.
4. Ensuite endo/activité puis clamp/physio, à partir de cette valeur PAI.

**Identique** `f61474bb` / `90a95b7b` / `d8a61cbc`. Porter le câblage tel quel = fidélité tip **et** no-op ISF sur pred/SMB. Appliquer ×0.9 **après** PAI serait un changement clinique vs tip — **hors lot**, interdit ici.

### 3.4 Call-site COB (préexistant, pas #101)

`estimateUndeclaredVirtualCob` n’est appelé que depuis `applyAdvancedPredictions`, lui-même uniquement sur le bypass T3c legacy (`executeT3cBrittleMode…`). Le pipe principal `runAdvancedPredictionsAndPredPipePrep` injecte `mealCOB` / advisor **sans** `UndeclaredCobEstimator`. **Même structure sur `f61474bb`.** #101 change le helper, pas le câblage.

Effet du gate, quand l’estimateur tourne (pref on, COB déclaré = 0, chemin T3c `applyAdvancedPredictions`) : une montée ≥ 11 n’est plus coupée par `hr_inflammation`. Grams ajoutés à `effectiveCOB` des courbes (TBR anticipation). Commentaire objet : **jamais un SMB autonome**.

⚠️ **ASYNC IMPACT** : aucun. Helper pur, pas de coroutine / Flow / callback. `heartRateBaselineIsReal` local au tick, réécrit à chaque passe HR. Le snapshot physio lu par le COB estimator est le même que le tick (commentaire existant « Read-only w.r.t. the async physio / Ra state ») — **préexistant**, pas #101.
