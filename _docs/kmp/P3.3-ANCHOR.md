## 3. Fidélité clinique vs tip

### 3.1 `RiseCeilingGuard` — deux conditions

Relu côte à côte `origin/dev_OAPSAIMI:plugins/aps/src/main/.../smb/RiseCeilingGuard.kt` (`acdc2b118e`, blob `5741c83dfb`) vs `bc882328:plugins/aps/src/commonMain/.../smb/RiseCeilingGuard.kt`.

Règles (ordre, identiques) :

1. `isAtCeiling` : `units` fini et `> 0`, et pile sur `ceilingU` **ou** `highGlucoseCeilingU` à `1e-3` U près. Un plafond non fini / ≤ 0 ne matche rien. Zéro / NaN / négatif n’est jamais « au plafond ».
2. `nextRepeatCount` : pas au plafond → 0. Premier tick / trou `> 15 min` / horloge arrière → 1. Sinon `previous + 1`.
3. `evaluate` : pas au plafond → `not_at_ceiling`. Delta null / non fini → `no_rise_data` (rien n’est refusé). `repeats < 3` → `too_few_repeats`. `delta < 8.0` → `rise_too_small`. Sinon `rise_ceiling_repeat` + `block=true`.
4. `shouldWithhold` : `armed && block && !user && units > 0`. Désarmé → toujours false → tick bit-identique à avant le geste.

Dose : l’objet est pur. Le geste dose est `finalUnits = 0.0` au call-site DetermineBasal, **après** l’effort SMB, **avant** le charge SlowCarb. Le TBR n’est pas dans ce bloc.

Les **deux premiers** ticks d’une montée au plafond ne sont jamais refusés (`MIN_REPEATS=3`). Conséquence mesurée (KDoc tip) : pendant une montée rapide on peut **courir plus haut** après un repas, parce que les répétitions de plafond sont retenues.

### 3.2 Pref OFF + ombre

`BooleanKey.OApsAIMIRiseCeilingGuard.defaultValue = false` (tip et study). Call-site :

```
RiseCeilingGuard.shouldWithhold(
```

Désarmé : rien n’écrit `finalUnits`, la console ni `rT.reason`. Le verdict et `rise_ceiling_guard_*` partent quand même. `rise_ceiling_guard_withheld_u` n’est rempli que si `block` (absent ≠ zéro).
