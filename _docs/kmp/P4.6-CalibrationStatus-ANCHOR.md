## Ce que `status()` renvoie

Ref `LinearCalibrationPlugin.kt` L209–224. L’horloge est `dateUtil.now()`. L’ordre est strict :

1. Pas de `SENSOR_CHANGE` (`getLastTherapyRecordUpToNow`) → `NoSession`. Les entrées ne sont pas lues.
2. `now < sessionStart + 2 h` → `WarmUp(warmUpEndsAt)`. Les entrées ne sont pas lues.
3. `entriesForFit` puis `fitLinearCalibration` null → `NeedMoreEntries(entries.size)`.
4. `!fit.isApplicable` → `UnsafeFit`.
5. `FitMode.OffsetOnly` → `AppliedOffsetOnly`.
6. `FitMode.SlopeClamped` → `AppliedSlopeClamped`.
7. Sinon → `Applied`.

Le fit est le fit brut. Pas de mélange de péremption (`blendTowardIdentity`). La santé (P3.8), le trou (P4.5b) et les préconditions ne sont pas appelés.

`CalibrationStatus` est le sealed interface de sept cas, ref `core/interfaces/.../calibration/CalibrationStatus.kt` L13–34. `WarmUp.warmUpEndsAt` est un `Long` epoch ms. Pas d’`Instant`, pas de type Android.

`NoCalibrationPlugin` L41 renvoie `Applied`. KDoc de l’interface, ref `Calibration.kt` L52–59 : le plugin par défaut n’a rien à ajuster.

## Frontière C5 — `isApplicable`

| | Expression |
|---|---|
| Ref `CalibrationMath.kt` L166 | `slopeInRange && correctionInRange && lowEndSafe && highEndSafe` |
| Study `CalibrationMath.kt` L76 | `slopeInRange && correctionInRange` |

`status()` appelle le `isApplicable` study tel quel. `lowEndSafe` et `highEndSafe` ne sont pas ajoutés. Tant que C5 n’est pas porté, study peut renvoyer `Applied` là où la ref renvoie `UnsafeFit`. L’écart inverse existe aussi : study peut renvoyer `UnsafeFit` là où la ref renvoie `Applied`, parce que `correctionInRange` study est borné des deux côtés.

Le KDoc ref au-dessus de `LOW_MGDL` (L21–32) cite deux entrées, capteur 110 → 135 et 180 → 175, et la droite géométrique de pente ≈ 0,571. Ce n’est pas le résultat de `status()` sur ces deux entrées. `fitLinearCalibration` de la ref force `OffsetOnly` dès qu’il y a moins de `MIN_ENTRIES_FOR_SLOPE` entrées (`3`, déclaration L87, usage L192). Les écarts sont +25 et −5, l’offset est +10, la correction au centre est +10. La ref répond `AppliedOffsetOnly`. Study ajuste la pente (`Full`) et répond `Applied`. Le test d’ordre ne présente pas cette paire comme un `UnsafeFit` de la ref.

L’exemple où la ref répond vraiment `UnsafeFit` a trois points : 110 → 135, 145 → 155, 180 → 175. Les deux côtés ajustent la pente (`Full` : trois entrées, écart capteur 70 ≥ 54). Poids égaux (horodatage = `now`) :

| Grandeur | Valeur |
|---|---|
| pente | 4/7 ≈ 0,57142857 |
| offset | 505/7 ≈ 72,142857 |
| correction à 100 mg/dL | 205/7 ≈ +29,2857, dans `[-30, 30]` et ≤ 30 |
| correction à 40 mg/dL | 385/7 = +55, au-dessus du plafond ref `CORRECTION_AT_LOW_MAX` = 20 |

`lowEndSafe` échoue côté ref, donc `UnsafeFit`. Study ne regarde que la pente et le centre, `isApplicable` est vrai, `status()` répond `Applied`. Le test `a_fit_the_reference_rejects_at_the_low_end_stays_applied_until_c5` verrouille ces fractions et ce `Applied`.

Écart inverse, non porté, pas un second test : `correctionInRange` study (`CalibrationMath.kt` L75) est `correctionAtCenter` dans `[-30, 30]`. La ref (L155) ne borne qu’en haut (`correctionAtCenter <= CORRECTION_AT_CENTER_MAX`, soit ≤ 30). Une correction au centre sous −30 peut donc être `UnsafeFit` dans study et passer le centre dans la ref (le plancher bas de la ref est `lowEndSafe`, pas cette porte). `status()` lit le prédicat study via `isApplicable`. On ne le change pas.

Autre écart du même commit `1b81e356c8`, non porté, qui change le mode avant `isApplicable` : `MIN_ENTRIES_FOR_SLOPE = 3` (ref L87 et L192). Deux points écartés sont offset-only dans la ref, et peuvent être `Full` ou `SlopeClamped` dans study. Le cas `AppliedSlopeClamped` du test utilise trois points sur la droite de pente 12/7, pour que les deux fits tombent sur `SlopeClamped`.
